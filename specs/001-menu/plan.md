# 实现计划

1. 建立纯 Python 菜谱、用料及三档库存模型，准备三人份样本。样本覆盖汤、主食、动物性辅材、少量用料及常备用料。
2. 实现候选过滤、三菜组合、稳定排序和换菜。单换保留槽位，整换排除原菜谱集合。
3. 将规格表中的每个场景映射到自动验收。完成前两项及算法验收后，进入库存闭环。

## T5 本地运行与验收

使用 Python 3.11+ 和 SQLite 3.38+。当前项目数据库已初始化。新数据库先运行 `sqlite3 db.sqlite3 < outputs/001_init.sql`。

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-test.txt
.venv/bin/python -m ai_menu.seed_recipes
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python -m uvicorn ai_menu.api:app --host 127.0.0.1 --port 8000
```

本地打开 http://127.0.0.1:8000/docs。补录番茄、生菜或土豆等受限食材后生成菜单。菜单写入携带今日上海日期作为 `X-Menu-Date`，所有写入携带 UUID 作为 `Idempotency-Key`。库存文本预览使用 T4 的中文规则。实际使用时打开 http://127.0.0.1:8000/。


## T6 范围与验收

- FastAPI 同源提供本地 H5，默认通过 http://127.0.0.1:8000/ 访问。家庭登录与公众号接入移出本轮范围。
- 在手机尺寸的浏览器视口走通库存查看和录入预览、今日菜单、换一道或换整套、确认实际做过的菜和剩余状态、查看做菜历史。
- FastAPI 运行期间，每天上海时间 06:00 起自动生成，最多约 15 秒后触发。后台在 06:00 后启动时补跑；H5 打开时也会补生成缺失或库存已变化的菜单。定时任务与页面使用同一个 SQLite 数据库。同日重复执行依靠日期对应的幂等键，已确认菜单保持冻结。

验收记录：首页与静态资源、定时边界、同日重放、已确认菜单保留和库存业务接口测试已通过。本机 HTTP 已验证。手机尺寸浏览器点按验收待做。

## 大模型库存录入

复用现有模型配置及请求客户端，替换预览的正则语义解析，保留版本、确认事务和名称校验。用模拟模型验证原句、别名、新食材入库和错误处理。

库存诊断沿用 503 错误代码，增加结构化原因和可用的上游状态。由模型客户端分类，在 API 层记录告警，H5 根据原因显示提示。用模拟上游和无配置实例验证。

为库存预览提交按钮增加加载状态，在请求的开始和结束时切换。沿用现有提交锁和错误处理，验证成功和失败都能恢复按钮，并检查减少动态效果样式。

在预览区加入独立的加载卡片，与请求并行计时，结束时重置可见状态。更新 HTML 的静态资源版本，验证快速成功、慢请求和失败，也验证旧预览在等待期间隐藏。

在 H5 增加库存卡片、搜索、状态筛选和分批展示。将食材图片作为本地静态资源，验收匹配、翻批、空状态及窄屏布局。

将现有三个区块接到同一套基于 URL 片段的导航，复用现有渲染和操作逻辑。验收默认视图、入口高亮、直接链接、内部跳转与窄屏导航。

抽取统一的食材缩略图渲染，接入菜单和历史。新增独立图片模型配置、生成接口和与数据库关联的本地文件缓存。验证生成结果复用、错误回退、菜单和历史的图片数量限制及旧历史兼容。

统一记录图片接口的配置、模型和本地存储失败。模拟各类错误，核对 503 响应与后台日志中的诊断字段。
