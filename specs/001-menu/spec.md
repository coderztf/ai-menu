# 001 按家庭库存推荐和更换菜单

## 用户场景

一家三口打开今日菜单，看到能用手头食材做的三道家常菜。对其中一道不满意时，可以保留其余两道换一道，也可以换整套。

## 行为规格

| 编号 | 给定与操作 | 预期结果 |
|---|---|---|
| MENU-01 | 有足够食材和合适菜谱，生成菜单 | 三道不同的三人份家常菜，至少一道含肉、一道纯素。蛋菜可作为第三道，汤和主食排除。纯素按全部必需食材判定，包括辅材 |
| MENU-02 | 猪肉、鸡蛋或常备辅材未录入；受限食材缺行或用完 | 常备用料可用；使用不可用受限食材的菜排除 |
| MENU-03 | 受限食材为少量 | 仅匹配标明接受少量的菜谱，同一食材最多占一道。充足食材可以共用 |
| MENU-04 | 有多套合格组合 | 用已有设计的评分与稳定破平选择，优先用掉标记优先和少量的食材，并考虑过去七天实际做过的菜 |
| MENU-05 | 换第一、二或三道 | 其余两道菜及位置保留，目标槽换成不同菜谱，并重新检查整套组合 |
| MENU-06 | 换整套 | 至少有一道菜发生变化。只交换原菜位置视为同一套 |
| MENU-07 | 没有合格组合或没有替换方案 | 初次生成返回候选不足；换菜失败保留原菜单 |
| MENU-08 | 任意生成或换菜请求 | 库存状态和库存变更记录均无变化 |

## 首个增量的完成条件

用固定菜谱与库存样本验证 MENU-01 到 MENU-07。纯 Python 推荐模块接收菜谱、库存和历史，返回菜单或候选不足，调用前后的输入一致。MENU-08 在接入持久化后，通过事务前后的查询验收。

后续增量依次交付自然语言录入与确认、菜单持久化与做菜确认、每日自动生成与本地 H5。接口和事务以 MVP 技术设计为基础。

## 库存录入新增食材

给定食材字典没有黄瓜，输入“买了2根黄瓜”时预览标记新增食材，确认后一次提交创建食材、别名和库存。重发同一请求只保留一条食材与库存变更。已有名称或别名复用原食材，常备食材维持常备策略。手动录入提供同一新增能力。新食材可参与使用该食材的菜谱匹配。

## 大模型库存录入

一句话录入由配置的大模型识别食材、库存状态、备注和优先使用标记。「今天又买了一些平菇、还有不少虾仁」应预览平菇和虾仁两项，「一些」按少量、「不少」按充足。已知名称和别名匹配已有食材，新食材在确认后入库。重复、常备或无法判断的条目提示人工处理。模型不可用或响应无效时返回可重试错误，预览不写库存。

库存模型的 503 响应应包含可定位的错误原因。页面和后台区分配置缺失、服务拒绝、超时、连接失败及无效响应。诊断只记录安全的原因代码和上游 HTTP 状态，避免记录密钥、模型地址、录入原文和模型响应正文。

点击「预览录入」后，库存预览请求期间显示加载动画和「正在识别库存…」，并禁用本次提交按钮。请求成功或失败后恢复按钮，继续显示预览结果或错误提示。系统偏好减少动态效果时保留加载文字并停用旋转。

再次预览时，等待期间用独立的加载卡片替代上一份结果，提交按钮仍显示加载状态。快速返回时加载卡片至少显示 350 毫秒。失败时恢复上一份预览，成功时显示新结果。

## 库存展示

库存以响应式卡片展示，保留名称、状态、备注、优先使用标记。常见食材显示本地缩略图，其余使用分类占位。支持名称搜索和状态筛选，显示匹配数量，每次最多新增展示 12 项。筛选条件变化后回到首批，无匹配项时显示空状态。

## 主界面布局

菜单、库存、做菜历史通过顶部导航切换，一次展示一个视图，默认打开菜单。导航显示当前视图，支持直接链接及浏览器前进、后退。库存录入入口和手动调整链接仍可跳到对应位置，切换视图保留页面内尚未提交的表单内容。窄屏导航保留三个入口。

## 菜单、历史与 AI 食材图片

今日菜单每道菜展示最多三种食材缩略图及名称。做菜历史每条展示最多四种实际做过的菜所用食材，同一食材只展示一次。各视图共用本地图片和占位图。库存无图食材可手动发起 AI 生图，生成后按食材 ID 本地保存，并在三个视图共用。浏览页面不调用生图模型。未配置或生成失败时保留占位并提示原因。

图片模型在 `ai-config.yaml` 的 `image_ai` 段配置 `url`（完整 Chat Completions 或 Images Generations 接口）、`model` 和 `api_key`。环境变量 `MENU_IMAGE_URL`、`MENU_IMAGE_MODEL` 和 `MENU_IMAGE_KEY` 可逐项覆盖。图片模型仅接收食材名称及拍摄风格提示。

食材图片生成返回 503 时，后台记录食材 ID、失败原因和可用的上游 HTTP 状态码。日志不包含密钥、模型地址、请求或响应正文。

Kimi 图片配置通过 Chat Completions 的 JSON 模式生成正方形 SVG 食材插画，兼容已填入的 Moonshot `/v1/images/generations` 地址。服务端只接受限定的静态图形和属性，拒绝脚本、链接、外部资源、样式注入和超大响应，经校验重建后作为本地图片提供。旧 WebP 缓存继续可读，其他已配置的 Images API 仍可生成 WebP。Kimi 遇到普通 429 或 504 可退避重试，额度不足直接返回。

首次 SVG 响应格式或校验不通过时，允许重新生成一次，只有通过校验的结果才能缓存。
