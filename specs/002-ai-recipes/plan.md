# 002 AI 菜谱实施计划

以 [功能规格](spec.md) 为准。启用模型后，每日生成和换菜根据库存获取候选菜谱。SQLite 保存选中菜谱和菜单快照，沿用库存确认与做菜历史。模型服务尚未选定，先通过可配置的 chat-completions 接口和模拟服务完成开发。

## 实现顺序

1. **模型适配。** 实现可替换的候选生成接口。后端从环境读取服务地址、模型名和可选密钥。模型调用在写事务外执行，并将不可用或无法解析的响应映射为可重试错误。
2. **候选校验。** 根据当前食材字典校验用料代码、菜谱结构、菜品种类和重复菜名。将通过校验的候选交给现有推荐规则，验证三人份三道菜的库存与荤素约束。首版仅向模型提供充足或常备的食材。
3. **菜单接入。** 让每日生成、单换和整换复用候选生成。保存前检查菜单与库存版本，原子写入选中的菜谱和快照。单换保留两道原菜的槽位。失败时保留原菜单与库存。
4. **本地交付。** H5 沿用现有操作，并显示模型错误。定时任务复用生成服务。应用默认要求模型参与菜单生成和换菜。
5. **真实服务联调。** 选定服务后配置并重启，用 H5 核对生成、单换和整换、库存不变、失败提示和定时触发，再记录具体服务与模型的验收结果。

## 大模型作为应用默认推荐来源

应用入口要求模型参与新菜单生成和换菜。保留已有菜单的重放与读取、库存版本校验及候选约束。通过模拟模型验证生成链路和缺少配置时的错误。

复用模型客户端的结构化错误，在菜单服务统一记录诊断并传到 API 和 H5。用模拟模型验证响应、菜谱校验和上游错误分类，同时检查日志内容及前端提示。

为菜谱模型调用传入独立超时，验证配置默认值、覆盖顺序和无效值。清空示例配置中的实际凭据，保留参数示例。

将换菜接到后台工作线程并增加任务查询接口。复用菜单事务和模型诊断，在 H5 提示任务进度并轮询结果。验证提交与查询、重复请求、成功与失败、并发提交和原有版本约束。

取消菜谱模型调用的应用层超时，移除旧配置入口。使用模拟传输验证生成及换菜共用无超时调用，库存识别仍使用 35 秒。
